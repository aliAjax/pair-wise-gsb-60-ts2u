# 医疗器械上市后安全信号核查与处置平台

面向医疗器械上市后安全团队的本地工作台，用于合并投诉、维修、不良事件和现场报告，维护证据矩阵、调查任务、风险状态、结论版本和审计轨迹。

## 技术栈

- SvelteKit 2 + Vite + TypeScript
- Skeleton UI + Tailwind CSS
- Svelte stores
- SvelteKit Form Actions
- TanStack Query for Svelte
- Zod

## 主要工作区

- `/`：开放信号、高风险信号、任务和逾期总览
- `/signals`：关键词与多条件筛选、人工登记新信号、发起合并
- `/signals/merge`：信号合并工作台（选主/来源信号、预检冲突、逐项写入、失败恢复）
- `/signals/[id]`：证据矩阵、状态流转、补充证据、结论版本、重新打开和审计
- `/trends`：发生率趋势与阈值核对
- `/batches`：批号覆盖与报告追踪
- `/audit`：跨信号审计时间线和 JSON 报告导出

## 信号合并规则

- 负责人指定一个**主信号**与多个**来源信号**：证据矩阵、调查任务、结论版本、审计记录接入主信号，关联批号并入批号覆盖。
- 来源信号转为「已并入主信号」只读去向（`mergedInto` 指针），保留全部原始内容备查。
- 每个信号带 `revision` 乐观版本号；两个页签同时处理同一批来源信号时，后到方在首次写入前发现版本已变，会被阻止并提示先复核对方刚补的证据，绝不静默覆盖。
- 合并落为可审计的写入 journal（证据/任务/版本/批号/审计/去向/汇总各自独立条目）。某一项写入失败后可从断点「恢复未完成项」，重试按条目幂等，不重复接入。
- 主信号已有结论版本时，来源结论以「来源结论」标记并排保留，不替换主结论，留复核人比对；主信号若已关闭，合并后自动转入复核。

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18460`。

## 构建与检查

```bash
npm run check
npm run build
```

无后端服务，页面使用确定性模拟数据，并将信号、证据、版本和审计记录持久化到浏览器 `localStorage`。关键表单先经过 SvelteKit Form Action 与 Zod 校验，再写入本地 store。
