# 医疗器械上市后安全信号核查与处置平台

面向医疗器械上市后安全团队的本地工作台，用于合并投诉、维修、不良事件和现场报告，维护证据矩阵、调查任务、风险状态、结论版本和审计轨迹。

## 技术栈

- SvelteKit 2 + Vite + TypeScript
- Skeleton UI + Tailwind CSS
- Svelte stores
- SvelteKit Form Actions
- TanStack Query for Svelte
- Zod

## 主要工作区

- `/`：开放信号、高风险信号、任务和逾期总览
- `/signals`：关键词与多条件筛选、人工登记新信号、勾选信号发起合并
- `/signals/[id]`：证据矩阵、状态流转、补充证据、结论版本、待复核来源结论、重新打开和审计
- `/trends`：发生率趋势与阈值核对
- `/batches`：批号覆盖与报告追踪
- `/audit`：跨信号审计时间线和 JSON 报告导出

## 信号合并语义

安全评审组在投诉、维修与现场报告中登记的同一故障会被拆成多条信号，台账页支持勾选后由负责人指定**主信号**与**来源信号**进行合并：

- **内容接入主信号**：证据矩阵、调查任务、审计记录接入主信号，关联批号并入批号覆盖并集，报告数/暴露量/发生率重新聚合；证据、任务、审计均保留原始 ID（`originId`）与来源标记。
- **来源信号只读留痕**：来源写入 `mergedInto` 去向（主信号、合并人、时间），详情页与所有写表单进入只读态；已封口信号不能再次并入，也不能作为主信号被反向并入。
- **结论并排不替换**：主信号已有结论版本时，来源结论进入「待复核的来源结论」区与主结论并排保存，复核人逐条**采纳**（生成带溯源的主信号新版本）或**驳回**，不自动覆盖。
- **乐观并发冲突保护**：每个信号带 `revision` 修订号；两个页签同时保存同一批来源时，后来方提交前会重新读取持久层，发现主信号或来源已被改写即整体停止并报告冲突，不会盖掉对方刚补的证据。核对后可「刷新基线并续跑」。
- **失败可恢复、重试不重复**：合并作业（四个阶段 × 每个来源）持久化在 localStorage，单阶段写入失败后已接入内容即时可见；续跑时跳过已完成阶段，并按 `originId` 去重。面板中可勾选在指定阶段注入一次模拟写入失败用于演示。

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18460`。

## 构建、检查与测试

```bash
npm run check
npm run build
npm run test:merge   # 合并语义无头测试：幂等恢复 / 并发冲突 / 结论并排 / 批号覆盖
```

无后端服务，页面使用确定性模拟数据，并将信号、证据、版本和审计记录持久化到浏览器 `localStorage`。关键表单先经过 SvelteKit Form Action 与 Zod 校验，再写入本地 store。
